## Как это запускается

`generator` и `seed` — модули MAM, а не самостоятельные пакеты. Чтобы собрать, их надо положить в воркспейс MAM под именами, из которых складываются имена классов:

```
mam/giper/bench/   ← generator/  (класс $giper_bench)
mam/giper/seed/    ← seed/       (класс $giper_seed)
```

Дальше из корня воркспейса:

```bash
npx mam giper/bench
node giper/bench/-/node.js role=list master=none rate=4000 duration=1
```

Полный порядок прогона на стенде — в [generator/README.md](./generator/README.md).

**Модули нельзя складывать в одну папку**: MAM собирает все `.node.ts` модуля в один бандл, и оба скрипта, самозапускающиеся на верхнем уровне, стартуют вместе. Это уже стоило одного потерянного прогона.

## Главное из результатов

- Потолок одного узла — между 200 и 400 операциями в секунду, при этом ядро загружено лишь на 55.6%, то есть упор не в процессор.
- Цена записи на клиенте растёт линейно с историей ленда: суммарная работа квадратична. Это главное ограничение.
- Рассылка подписчикам дешёвая: с 1 до 25 читателей загрузка растёт с 5.8% до 7.4% ядра.
- Ветки `sand-ordered-linear` и `sand-ordered-linear2` квадратичность не убирают, в продакшен не идут.
